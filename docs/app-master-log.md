# App Building Master Log (mirror)

Live doc: "App Building Master Log" (Claude Docs artifact https://claude.ai/artifact/WxmMqZEw3zH8m7VmiBJdGU). This file is the project copy every app chat can read. Started 12/11/2026.

## How to keep it up to date (every app chat)
When an app ships something seminal — a pattern another app should copy, a fix for a failure any app could have, an interface choice that changed how an app feels, or a new way the apps work together:
1. Add a row at the top of the Upgrade log here AND in the live doc: `date · app version · upgrade · why it matters elsewhere`.
2. If it's a lasting pattern, add or update the line in the matching section.
3. Read this file first (other chats write it too) and write it back whole; never overwrite blindly.
Routine fixes and app-specific content stay in that app's own notes.

## Principles
- Offline first; the device is the source of truth; sync is a merge, never a replace.
- Never lose a record: newest-wins per record, tombstones, snapshot before anything destructive, Undo after.
- Nothing is written without a tap (proposals from other apps, imports, rota changes, AI suggestions).
- Every hidden gesture has a visible twin.
- Plain words, exact numbers, dd/mm/yyyy, metric.
- One family look (orange accent), several interfaces per device (Arcade / Clean / Paper) + text size.
- Phone and desktop both first-class (desktop: wide layouts, side rails, shortcuts).
- Test like a user, then like a saboteur.
- Before a big version, interview the user in rounds (goal, style, time, coach autonomy, voice, look, game level, devices, cuts) and save the answers as a blueprint with waves (Mephisto 12, Orange 9).

## Cloud and sync
- Layout: `My Apps/Rotas`, `My Apps/<App>/` (large data), `My Apps/hub/<app>/status.json`, `hub/<app>/data/` or `state.json`, `hub/<app>/backups/`, `hub/citrus/plan.json`. Nothing at the Drive root. One shared OAuth client, full `drive` scope.
- 12 rules (Citrus HUB.md): find before create; one lookup per path at a time; update in place (PATCH); serialize writes to one file; download as bytes; a lost create answer → look up before resending; twins → newest wins, rest binned (folders: keep oldest, move contents); fingerprint writes in `appProperties.h`; revision check (`appProperties.rev`) before overwriting shared state; changes feed + full pass every ~12 h; retry only what's safe (30 s timeout, jittered backoff, offline fails fast); renew tokens from a tap on phones.
- Sync engine: pull → merge newest-wins → push changed shards → re-list before/after upload (mismatch = merge again); safety stop when the device holds fewer records than the cloud; one sync at a time (Web Locks); debounce 8 s (60 s mid-session), pull on return and every 5 min.
- Repair on read: damaged/duplicate/half-written cloud files are merged, rewritten whole, spares binned (Orange 8.8.0). Settings merge per field via `valueAt` (Orange 8.10.0).
- Data upgrades must not look like edits: stamp the record 1 ms after its last version and move the sync base forward, and run the same converter on imports and pulls (Orange 9.1.0 `applyUpgrades`, `repair.js normalizeIncoming`).
- Single-JSON-state apps (Mephisto 12.5.1 `v2/c_cloud.js`): reset/restore/replace stamp an `_epoch` that wins the merge; settings carry per-key `_ts` (unstamped loses, so a fresh device never overwrites); cards win by last review time; an unreadable cloud file aborts the sync and is copied aside, never overwritten; server-side daily copy before each write; index-keyed lists get stable keys during the merge so it is deterministic, and keep the local order afterwards so an open session never points at a different item (Mephisto 13.0.0 `denormC(o,pref)`). Selective resets use one epoch per group (`_epochs`), applied per key, and are marked only after the user confirms (Mephisto 12.6.1).

## Data safety and stability
Daily rolling cloud backups (7 daily + 4 weekly, one file per phone per day; Bring back writes ticked records back as new edits, Orange 9.1.0) · snapshot before destructive actions + Undo · safety stop on counts · repair on read · load-time clean-up in memory, unreadable records set aside, never written back (Orange 9.1.0) · resumable uploads by fingerprint · error boundary with Reload / Download a backup / Repair · save-failure and storage-full banners · validated storage on load · `navigator.storage.persist()` · BroadcastChannel between tabs + `onversionchange` reload · one writing tab: Web Lock held for the app's life, a second tab offers "Use here" and takes the lock over before reading (Yuzu `src/lib/tabs.ts`) · the study day turns over on an open app (timer + visibilitychange, Yuzu `watchDayTurn`) · one finish at a time · versions with diff + Restore (Dragonfruit) · privacy lock (Dragonfruit) · CSV formula guard.

## Interface and design
- Interfaces (Orange 8.12.0): Arcade (8-bit pixel font, notched square panels, bevels), Clean (dark, soft corners, system type, flat), Paper (light; every colour scale flipped by a generated stylesheet). Text size Small/Normal/Large (root 14/16/18 px). Colour themes work in all. Built with `data-ui` / `data-size` on `<html>` applied before first paint; all colours are CSS variables.
- Bassiet tokens: accent #F28A1B / #FFA040, orange text #A24B00 / #FFB566, bg #F3F4F9 / #12141F, surface #FFFFFF / #1B1E2D, line #C6CCDC / #383E57, text #15182A / #ECEEF7, muted #566079 / #9CA3BE; Pixelify Sans, Source Sans 3, JetBrains Mono; 4 px radius, 2 px borders, hard `0 2px 0` shadow.
- Hand kit (ui-kit.md): hold to explain, hold menus, sliders/wheels, drag to reorder, swipe cards, pull to sync, actions at the bottom.
- Layouts: phone bottom bar + sheets; desktop ≥1440 px two columns with a sticky action rail (Dragonfruit Cockpit); desktop ≥1024 px two panes from one component tree — the main panes are values rendered one at a time on a phone or side by side on a wide screen, Alt+1/2/3 tabs (Orange 9.0.0); keyboard shortcuts. System Back steps back inside the app: History API entries with the stack in `history.state` (Galen 7.1.0 `80-app.js`).
- Stage themes, sound and controllers (Mephisto 12.0.0): a story/level stage owns the whole look via `data-realm` beside `data-ui` (g_gothic.css); WebAudio soundscape with no files (c_sound.js); Steam Deck gamepad: A select, B back, D-pad focus, L/R tabs (c_pakt.js).
- Story worlds (Mephisto 13.0.0 `v2/x_story3.js`, `c_story3.js`; claude/world-kit.md): give the world a human stake that returns (one recurring scene after each boss), a mid-point reversal, choices, documents, and a real end state; type scene lines (narrator, voices, document, choice) and play them all through one reader.
- Lenses as filters (Bassiet wave 1): a textbook chapter carries callouts tagged by subject; a sticky toggle bar shows or hides each subject, and interactive figures re-render only their view so controls keep focus (figs.js, app-dive.js).
- Course outlines (Galen 7.0.0 `src/03b-outline.js`): each topic area is a list of chapters (aim, what you will be able to do, linked items, the trap, the pearl), ids validated at build by check.js, with practice scoped to one chapter.
- Study + reference (Galen 7.0.0 `rpRender`): at ≥1100 px a capture-phase click hook opens a sign or technique beside the drill in a side pane instead of navigating away.
- Controls all at once (Yuzu 1.7.0 `src/lib/gamepad.ts`, `src/ui/Shortcuts.tsx`): pad buttons are turned into the app's own keys while studying and into a visible focus walk elsewhere; mouse hover shows hold hints; right-click is the hold menu's twin; "?" (or View) lists keyboard and pad side by side. No mode switch.
- Free assets (Mephisto 12.0.0): the sandbox reaches only GitHub — GITenberg repos for PD texts and illustrations, google/fonts for OFL fonts (subset to WOFF), music21 corpus + Essen ABC for scores (assets/build_assets.py, build_music.py). Inline the subset fonts as base64 WOFF so artifact and PWA both work offline (Galen `tools/fonts.py`; no brotli in the sandbox, so WOFF not WOFF2). Once an app nears the artifact's 16 MB per-file limit, move media to real files and publish a multi-file artifact (page + supporting files; served types only, e.g. .json, .webp, .woff), the same tree the PWA precaches (Mephisto 13.1.0 build.py).
- Mood layers that can't cover content (Kumquat 10.0.0): ambient fog drawn as `body` background gradients scaled by a `--fog` variable, so cards and text always sit on top; whispers are pointer-events-none and brief. Guide reactions can borrow the top-bar title for a few seconds instead of a toast (Galen 7.0.0 `quip`).
- Motion budget: never animate backdrop-filter; put animated glows on small composited layers and pause them when hidden (Galen 7.1.0 `99c-D15-motion.js`).
- Organisation: Settings in labelled groups with a jump row, each saying whether it syncs or is device-only (Orange 8.11.0); one bottom dock (Orange 8.10.0).

## Input
Arabic-Indic/Persian digits, ٫ and decimal comma everywhere (Orange `lib/num.js`, Dragonfruit `entry.js`) · auto-advance complete values, "120/80" splits, dd/mm/yyyy auto-slashes · Tab/Enter survive re-renders · one unit setting, implausible values re-read in the other unit · durations as spoken ("6 months", "2019", "٨ شهر") · sliders change only after a touch · sane bounds · scores give no band until the result is settled (Galen 7.1.0 `96-calcs-labs.js`) · typed answers: compare forgivingly, but show what was forgiven (capitals, ß, umlauts) and make it count from an intermediate level (Mephisto 13.0.0 `spellNote`, `spellStrict` in c_core.js).

## Smart without a connection
Rules engines that read the user's own data: readiness from rota/sleep/feel/load/recovery adjusts today's targets (Orange 8.13.0); stalls get ranked causes with evidence and one-tap fixes (Orange 8.13.0); weak points ranked per muscle from dose, trend and balance, with one fix offered (Orange 9.0.0 `lib/weakpoints.js`); over-budget sessions trimmed by value — isolation first, weak points and compounds kept (Orange 9.0.0 `lib/trim.js`); a 6-week block review says what to change (Orange 9.0.0 `blockReview`); a heavy review load gets ranked causes too (Yuzu 1.5.0 `src/lib/diagnose.ts`: backlog, new-card pace, leeches, target recall, days off, tuning, each fix with Undo); daily load follows the day — shift days shrink the session, reviews are capped at the day's minutes and the rest deferred (Mephisto 12.5.2 `v2/c_learn5.js`); a mood switch reshapes the session and a night or post-night shift from Citrus defaults it to light (Kumquat 9.0.0 `roundPlanMood`, `shiftLoad`); entry sanity checks offer the likely fix (Orange 8.13.0); must-not-miss rules (Dragonfruit). Always: explain why, offer the fix, never apply silently, a switch to turn adjustments off.

## Claude inside the apps (Dragonfruit)
Scaffold from the app's rules → Claude writes from the user's words + scaffold → parallel calls for speed → senior check in the background as line edits → deterministic safety net (restore dropped sections, must-not-miss rules) → gaps as tap-to-fill questions → edits keep the rest consistent, user's own lines untouched → versions + self-test → honest degradation without Claude.

## Apps working together
- Status v1: app, title, icon, color, url, updatedAt, summary, today{date,done}, next, asks[] (slot free/before), pending[].
- v2: metrics[] (history, habits), progress[] (objectives), inbox[] (stable-id proposals: task/note/event), actions[] (deep links). Orange 8.12.0 sends sessions + sets this week, bodyweight, weekly-goal %, 3 actions, weigh-in proposal.
- Deep links: `<app>/?from=citrus&do=<id>` → jump there, consume params, show "← Citrus", link back `<Citrus>/?from=<app>`.
- Capture/share: Citrus `#capture=`, Yuzu Drive outbox, Orange rota share target.
- Learning apps feed Yuzu: weekly `yuzu_pack` files (mcq misses, basic formula cards, stable ids) in `My Apps/Yuzu/collection/inbox`, reviewed in Yuzu before adding (Kumquat 9.0.0 `sendToYuzu`; Bassiet `toYuzu` sends missed stain-test and duel questions). Language apps send `vocab` cards (word, article, plural, meaning, example, optional audio; no audio = the device's voice) — Mephisto → Yuzu, format in hub-contract.md (Yuzu 1.7.0).
- Cross-repo contract test: Orange's tests run Citrus's own `normalizeStatus`.
- Reasoning-app hand-off: learning apps write a case or gas as JSON into `My Apps/hub/handoff/` (Buffer 4.9.0 `buffer_handoff`: kind, title, gas or timeline); the reasoning app reads it later.

## Testing and release
Unit (with fake Drive incl. changes feed) → two-device sync convergence → real-browser run (~80 checks, offline start, no JS errors, no "undefined/NaN/null" on screen) → random-tap sweep (`monkey.mjs`, `FIND=1`) → simulated beta testers in roles. Pin the clock in date-bound tests (Citrus); pin date-sensitive features off for weeks-old fixtures (Orange readiness); clock-bound popups stay quiet under `navigator.webdriver` (Mephisto 13.0.0). Never rebuild the app while a browser run is serving it (Orange 9.0: a mid-run build failed the run). Serve the PWA shell in local tests, not the bare artifact HTML: without doctype and charset, non-ASCII identifiers fail to parse (Mephisto 13.0.0 `tests/run.sh`); without a doctype the page is in quirks mode and CSS class names become case-insensitive (`.zm` and `.zM` collide; Bassiet). Release: build → tests → bump → confirm Pages branch → push → notes, roadmap, this log. Say plainly what wasn't verified on real devices. Real-data probes in a saved browser profile must use the same port as the import and clear its HTTP cache and service worker first, or they test an old build (Yuzu `tools/probes/beta.ts`). Multi-week learner simulation: override `Date` in an init script and carry localStorage day to day (Mephisto 12.5.2 beta, `beta/r5/learner/lib.js`) — finds backlog and pacing bugs no single-day test can. Whole-campaign simulation: script a learner that answers every test and duel to the final boss, checking every gate and seal on the way (Bassiet). Gamepad without hardware: stub `navigator.getGamepads` in an init script and toggle button states (Galen 7.0.0). Content audits by an independent reviewer in role (a linguist for language, a story critic for the world) find what tests cannot (Mephisto 12.9.1, 12.10.0). Screens extended by many modules: register sections with a hook (`MOD.after`, Mephisto 13.1.0 `v2/c_mod.js`) instead of reassigning the function, and fail the tests if any section logs an error (tests/t131.js). Build guard for apps concatenated into one script: `node --check` plus a duplicate top-level name check, because a second function with the same name silently wins (Buffer build.py). Parallel improvement rounds (Bassiet v15): area testers first, then developers who each own separate files under one written contract (shared APIs, data fields, handoff notes), the coordinator relaying cross-file requests; test storage against a slow mock db, because in-memory tests hide failed and lost saves. Audit quiz answer-key positions and option lengths; shuffle options at display time. Enforce it in the gate with a bank lint, and run an independent release check on the merged build (Embergine 1.3.0 tests/lint_bank.py, verify-1.3.md). Parallel fix lanes: each fixer works in a private sandbox copy and hands back a diff; the lead merges with patch and git merge-file, then runs the full suite (Sinus dev/p2/, 13/11/2026). With git: one worktree and branch per lane, merge one lane at a time with unit tests after each, and keep one of any two lanes' overlapping fixes (Orange 9.1.0). When parallel agents stop mid-work (usage limit), save each working copy as a diff and merge anyway: union for same-point inserts, a character-level 3-way merge for shared long lines, a smoke test after every patch; then fix tests that assert behaviour a package changed on purpose (Kumquat 11.0.0). Big hardening pass (Yuzu 1.8.0): area testers write findings with IDs and repros; group them into packages, one developer per package in its own git worktree with its own CSS file and test ports; merge by hand, then run every suite and the real-data sweep on the merged build.
